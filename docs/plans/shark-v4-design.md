# Shark Agent V4 — Technical Design

## Overview

Shark Agent V4 is a production-grade software engineering orchestrator. It moves away from "guessing" and toward **mechanical enforcement**. It uses the V4 Factory to implement two distinct operational modes:

- **Shark Micro**: Sequential dual-brain (Plan ↔ Build) with mechanical switching
- **Shark Macro**: Parallel triple-brain racing (Execution + Reasoning + System)

Both are **tab-toggle agents** in OpenCode. The human is **never** in the build process.

---

## Core Philosophy

> "Production-grade software that works the first time, every time."

- **Zero tolerance on gate failures** — If a gate fails, the task is not done
- **Evidence is mandatory** — "I tested it" means nothing without proof
- **Context-firewalled brains** — Reasoning and execution are isolated
- **Guardian zones are sacred** — Scope containment is never bypassed
- **Auto-debug first** — 60% of errors can be fixed automatically
- **Iteration until production-grade** — Loop VERIFY until it passes or escalate to PLAN
- **The human is never in the build process**

## Gate Chain

```
PLAN ──► BUILD ──► TEST ──► VERIFY ──► AUDIT ──► SHIP
                          ↑       │
                          └───────┘ (iteration loop)
                          
If VERIFY fails 3x ──► back to PLAN (V1.0 ──► V1.1) with full context + debug logs
```

### Gate Definitions

| Gate | Input | Output | Blocking Criteria | Enforced By |
|------|-------|--------|-------------------|-------------|
| **PLAN** | User prompt | SPEC.md, Guardian config | Clear requirements, defined scope, acceptance criteria | Plan Brain |
| **BUILD** | SPEC.md | Implementation files | Files created per spec, no scope violations | Execution Brain |
| **TEST** | Implementation | Passing tests, coverage report | Tests pass, coverage ≥ 80% | Execution Brain |
| **VERIFY** | Tests pass | Production-grade verified code | No bugs, matches spec, pressure tested, 0 errors | **System Brain** (primary), Plan Brain (spec alignment) |
| **AUDIT** | Verified code | Security-clean | SAST clean, no secrets, dependency audit passed | System Brain |
| **SHIP** | Security-clean | Shipped artifact | Evidence archived, checkpoint created | System Brain |

### VERIFY Content (What "Pressure Testing" Means)

| Check | Purpose |
|-------|---------|
| SPEC.md alignment | Does code match what was specified? |
| Integration tests | Do components work together? |
| Edge case coverage | Are boundary conditions handled? |
| Theatrical code detection | Looks right but doesn't work? |
| Error handling | Are exceptions caught properly? |
| Performance smoke | Any obvious regressions? |

## Brain Responsibilities

### Shark Micro

| Brain | Role | Phases Active | Context |
|-------|------|-------------|---------|
| **Plan Brain** | Reasoning | PLAN, VERIFY (review) | T1 + T2 |
| **Build Brain** | Execution | BUILD, TEST | T1 only (clean) |

### Shark Macro

| Brain | Role | Priority | Phases Active | Context |
|-------|------|----------|--------------|---------|
| **Execution Brain** | BUILD + TEST agent | 100 | BUILD, TEST | T1 + injected context |
| **Reasoning Brain** | Context bridge + auto-debug | 90 | ALL (background until needed) | T1 + T2 |
| **System Brain** | VERIFY + AUDIT + SHIP enforcer | 80 | ALL (watching) | T1 + T2 |
| **Plan Brain** | Spec owner + escalation target | 95 | ALL (background monitoring) | T1 + T2 |

**Plan Brain in Macro**: Always active in background, monitoring spec alignment. Like a "dynamic active context watchdog powered by a model over an algorithm". Becomes primary when escalated to from VERIFY.

**Reasoning Brain in Macro**: Active through all phases. During VERIFY, it becomes the primary active agent "ruthlessly mechanically pressure testing everything". Real-time context injection to Execution Brain throughout all phases.

## Iteration Loop

```
User Prompt
     │
     ▼
PLAN (V1.0) ───────────────────────────────────────────► BUILD ──► TEST ──► VERIFY
     │                                                     ↑         │         │
     │                                                     │         │        fail
     │                                                debug log      │         │
     │                                                     └─────────┘         │
     │                                                      loop (max 3)       │
     │                                                                        │
     │                                                           3x fail        │
     └──────────────────────────────────────────── PLAN (V1.1) ◄───────────────┘
     │  (full context + all debug logs from V1.0)
     │
     ▼
BUILD (V1.1) ──► TEST ──► VERIFY ──► AUDIT ──► SHIP
```

**Debug Log Format (auto-generated by System/Reasoning Brain):**
```
ISSUE: {description}
LOCATION: {file:line}
ROOT_CAUSE: {analysis}
FIX: {specific instructions}
ITERATION: V1.N ──► V1.N+1
```

**V1.N Naming**: Every escalation to PLAN from 3 failed verifies triggers a new iteration (V1.0 → V1.1 → V1.2...). Context firewalling ensures clean separation between iterations.

## Architecture Components

### Shared Components (from V4 Boilerplate, copied self-contained)

- **StateStore**: Domain ownership enforcement
  - `execution-state`: Execution Brain (write), System Brain (read)
  - `thinking-state`: Reasoning Brain (write), Execution, System (read)
  - `workflow-state`: System Brain (write), Reasoning (read)
  - `quality-state`: Execution Brain (write), System (read)
  - `security-state`: System Brain (write)
  - `plan-state`: Plan Brain (write), Execution, Reasoning, System (read)

- **BrainMessenger**: Priority signaling
  - Priority levels: Critical > High > Normal > Low
  - Used for: context injection, derailment alerts, gate signals

### Guardian (Scope Containment)

**Default: SANDBOX mode (everything allowed)**

| Zone | Access | Notes |
|------|--------|-------|
| SANDBOX | Full | Default, nothing blocked |
| WORKSPACE | Full | Project directory |
| PERSONAL | BLOCKED | ~/.ssh, ~/.aws, Documents |
| SYSTEM | BLOCKED | /bin, /usr, /System |

Structure built for BALANCED/STRICT but left disabled for testing.

## OpenCode Plugin Integration

**Two separate tab-toggle agents on plugin load:**

- `shark-micro`: Shark Micro tab (like Spider/Hermes agents)
- `shark-macro`: Shark Macro tab

**Tools Exposed:**
- `shark-status` — Show current brain, gate, iteration state
- `shark-gate` — Manual gate evaluation
- `shark-evidence` — Evidence viewer

**Standard OpenCode tools:** Filtered based on current brain state and Guardian zone.

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Model for all brains | OpenCode's selected model | Simplicity first, custom config later |
| Dependency strategy | Self-contained (copied) | Every codebase should be self-contained |
| Guardian default | SANDBOX | Start permissive, enable restrictions later |
| Iteration threshold | 3 failures at VERIFY | Right default, configurable |
| Context injection | Synchronous | Real-time intelligence required |
| VERIFY enforcement | System Brain (primary) | Execution Brain is BUILD+TEST only |
| Escalation target | PLAN Brain | Human never in build process |

---

## Build Priority Order

1. **Plugin Foundation**: Copy V4 boilerplate shared components, set up directory structure
2. **Guardian**: Simple SANDBOX containment
3. **Evidence System**: .shark/evidence/ collection
4. **Gate Definitions**: PLAN → BUILD → TEST → VERIFY → AUDIT → SHIP
5. **Shark Micro**: Coordinator, Plan Brain, Build Brain, iteration loop
6. **Shark Macro**: Peer dispatch, Execution, Reasoning, System, Plan brains
7. **Context Library**: Copy shark-context/
8. **OpenCode Integration**: Two tab-toggle entries
9. **Testing**: Manual verification of both variants

## Differences from Spider/Hermes

| Aspect | Spider/Hermes | Shark V4 |
|--------|--------------|----------|
| Coordination | Agent delegation | Mechanical brain switching / peer racing |
| Context | Shared context | Context-firewalled brains (T1/T2) |
| Enforcement | Hooks + gates | Mechanical enforcement (cannot be bypassed) |
| Evidence | Optional | Mandatory for every gate |
| Scope | Agent-defined | Guardian-enforced zones |
| Debug | Manual escalation | Auto-debug (60%) before escalation |
| Iteration | Sequential waiting | Zero idle time (Macro racing) |
| Human | In the loop | **Never** in the build process |
| Verification | Post-hoc | **Iterative VERIFY loop** until production-grade |
