## ARCHITECTURE DECISION

**Decision:** Integrate Trident Brain modes into Kraken V2.0 brains

**Reasoning:**
- V2.0 has trust-based systems (believed 100ms timeout was real execution)
- Trident Brain has mechanical gate enforcement (proves execution happened)
- Problem Solving Mode 6-gate loop prevents fire-and-forget
- Code Review Mode catches simulated execution before deployment

**Alternatives considered:**
- Keep V2.0, fix individual issues → Would still have trust-based architecture
- Replace V2.0 entirely → Too costly, existing good components (Two-Layer Guardian)
- Add new layer on top → Would create complexity, not fix root cause

**Decision accepted because:** Addresses root cause (trust-based) not symptoms (fake execution).

## PROBLEM DECOMPOSITION

### Problem 1: FAKE EXECUTION
**Root cause:** `simulateTaskExecution()` returns success after 100ms, no real Docker spawning
**Fix:** Code Review Mode Layer 2 (Execution Verification) catches this before deployment
**Detector:** `setTimeout.*resolve.*success` regex

### Problem 2: FIRE-AND-FORGET
**Root cause:** `spawn_cluster_task` → success → MOVE ON, outputs never retrieved
**Fix:** Problem Solving Mode 6-gate evidence loop, OutputVerifier.claimRetrieved() required
**Gates:** G1 assumption → G2 outputs registered → G3 evidence → G6 verification

### Problem 3: NO DEEP PLANNING
**Root cause:** Planning Brain just assigns tasks, no first-principles analysis
**Fix:** Deep Planning Mode 3-gate generates injectable reasoning chain
**Output:** Structured document with core problem, principles, components, risks

### Problem 4: DISCONNECTED COMPACTION
**Root cause:** Four-tier exists but not integrated with problem-solving
**Fix:** Context Synthesis Mode 4-layer runs during active task, not just survival
**Triggers:** Token budget >65%, decision point, gate transition

## RISKS

### Risk 1: Code Review Mode has false positives
**Mitigation:** Tune detectors on known good code (V1.1) before deployment
**Detection:** Run on V1.1, should pass all layers

### Risk 2: 6-gate loop slows execution
**Mitigation:** Gates are state checks, not additional processing
**Measurement:** Log gate transition times

### Risk 3: OutputVerifier breaks existing code
**Mitigation:** Integrate gradually, test each phase
**Rollback:** Can disable OutputVerifier if needed (trust-based fallback)

### Risk 4: Council coordination adds complexity
**Mitigation:** Structured messages, not natural language
**Complexity budget:** Max 5 message types

## WHAT COULD GO WRONG

**Fix:** Tune threshold, run on V1.1 first
