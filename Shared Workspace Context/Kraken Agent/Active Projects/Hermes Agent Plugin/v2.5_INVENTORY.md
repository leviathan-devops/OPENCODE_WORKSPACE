## Key Design Decisions

### 1. Fork Only Activates for Hermes Sessions

All v2.5 hooks MUST have `isHermesAgent()` guard AND `.hermes/` directory check:

```typescript
// PRIMARY GUARD: Only fire when Hermes session is active
if (!existsSync(join(context.directory, ".hermes"))) return;
if (!isHermesAgent(agentId)) return;
```

### 2. Fork is Cooperative

Fork blocks tools by having tools CHECK ForkManager.isActive() before running. The SDK itself doesn't block.

### 3. Thread is Default

Most work should be Thread (async). Fork only for:
- Interactive planning (needs user conversation)
- Code review (needs user approval)
- Adversarial testing (needs user probing)

### 4. Skills in src/skills/

Skills are markdown files with YAML frontmatter, loaded at startup by SkillRegistry.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Fork blocks Spider Agent | CRITICAL | Double guard: `.hermes/` + `isHermesAgent()` |
| SDK doesn't support blocking | HIGH | Fork is cooperative (tools check isActive) |
| Skill loading complexity | MEDIUM | Use v2.5's simple YAML parser |
| EpisodeStore memory growth | LOW | Max 10 episodes per skill, prune old |
