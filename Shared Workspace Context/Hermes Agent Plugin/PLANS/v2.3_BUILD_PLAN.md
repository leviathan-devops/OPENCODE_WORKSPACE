## Executive Summary

## Phase 0: Build-Critical Bug Fixes

### Bug 1 — `secretScan` syntax error (CRITICAL)
**File:** `src/tools/security.ts` line 60
**Problem:** `export const secretScan=***` — invalid TypeScript, `=` instead of `tool({...})`
**Fix:** Wrap in proper `tool({...})` definition

### Bug 2 — `imports` path traversal (HIGH)
**File:** `src/tools/analysis.ts` line 85-87
**Problem:** `readFileSync(join(context.directory, args.path))` with no bounds check. `../../etc/passwd` reads outside project.
**Fix:**
```typescript
const fullPath = join(context.directory, args.path);
const resolved = resolve(fullPath);
const allowedRoot = resolve(context.directory);
if (!resolved.startsWith(allowedRoot)) {
  return `Error: Access denied. Path resolves outside project directory.`;
}
const content = readFileSync(resolved, "utf-8");
```

### Bug 3 — `grill` tool target mismatch (MEDIUM)
**File:** `src/tools/verification.ts` lines 16-17
**Problem:** `grill` tool expects `args.target` (a filename) but `verify` tool at line 62 calls it internally without setting a target. Also no path validation.
**Fix:**
1. Add path validation to `grill` (same pattern as analysis.ts fix)
2. `verify` tool must call `grill` with an actual file target, or remove the broken internal call

### Bug 4 — `sast_scan` silent failure (MEDIUM)
**File:** `src/tools/security.ts` line 43
**Problem:** `npx semgrep` exits silently if npx is unavailable — error swallowed with no message
**Fix:** Add availability check before semgrep:
```typescript
const npxCheck = spawnSync("npx", ["--version"], { encoding: "utf-8", timeout: 10000 });
if (npxCheck.error || npxCheck.status !== 0) {
  return `SAST unavailable: npx not found. Install Node.js to enable security scanning.`;
}
```

## Phase 1: Stub Replacements — Mechanical Enforcement

### 1.1 — TDD Enforcer: Make it actually block
**File:** `src/hooks/tdd-enforcer.ts` lines 30-46
**Problem:** Currently only injects `_tdd_violation` into args — doesn't prevent the write
**Fix:** Return blocking output instead of annotation:
```typescript
output.blocked = true;
output.message = `[TDD IRON LAW] Cannot write to ${filePath} without test file ${testFile}

RED (failing test) → GREEN (minimal code) → REFACTOR.
Write the test file first, then the implementation.`;
```

### 1.2 — Plan Validator: Connect to BUILD_INDEX.md schema
**File:** `src/hooks/plan-validator.ts`
**Problem:** Only regex-matches PLACEHOLDER_PATTERNS — no real validation
**Fix:**
1. Import BUILD_INDEX.md as schema reference
2. Validate plan has: exact file paths, actual code (not stubs), test commands, acceptance criteria
3. Check each phase has corresponding claim in `.hermes/claims.json`

### 1.3 — Brainstorm Gate: Actual blocking behavior
**File:** `src/hooks/brainstorm-gate.ts`
**Problem:** Stub that just blocks edits in ANALYZE phase
**Fix:**
1. Detect ANALYZE/PLAN phase entry
2. Block ALL file writes until design doc exists at project root
3. Require user approval marker in design doc before advancing phase

### 1.4 — Delegation Gate: Real SessionDB lookup
**File:** `src/hooks/delegation-gate.ts`
**Problem:** Only checks if an approval file exists — doesn't verify reviewer identity
**Fix:**
```typescript
const sessionDb = createSessionDB(context.directory);
const task = sessionDb.loadSession(taskId);
if (task?.metadata?.reviewerApproved !== true) {
  output.blocked = true;
  output.message = `[DELEGATION GATE] Task requires @reviewer or @quality-reviewer approval in SessionDB.`;
}
```
