## Corruption 4: Hook API Compatibility — `output.output` Undefined

**File:** `src/hooks/snapshot-writer.ts`, line 35

### Source (Potentially Broken)

```typescript
summary: output.output.substring(0, 500),
```

The `tool.execute.after` hook receives `(input, output)` where `output` is the tool's return value (a string), not an object with an `.output` property. `output.output` would be `undefined`. Calling `.substring(0, 500)` on `undefined` would throw a TypeError at runtime.

### Required Fix

```typescript
const rawOutput = typeof output === 'string' ? output : (output as any).output ?? '';
summary: rawOutput.substring(0, 500),
```

## Root Cause Chain

```
1. Developer writes v2.1 source with BOTH corruptions in place
2. Developer runs build (tsc)
3. Compilation fails at duplicate import (TypeScript Error: duplicate identifier)
4. Developer sees TypeScript error, fixes duplicate import
5. BUT: `secretScan=***` is a runtime-value corruption, not a TypeScript error
6. TypeScript compiles successfully after fixing duplicate import
7. Dist is generated with secretScan corruption intact
8. Developer runs the plugin, it crashes on first secretScan call
9. Developer writes BUGFIXES doc to document problems
10. Developer never rebuilds after fixing corruptions
```

The `secretScan=***` corruption would not produce a TypeScript error — it's a valid assignment where the right-hand side is a comment. The TypeScript compiler would see `export const secretScan/** comment **/ description: "..."` as a variable declaration with a JSDoc comment, followed by orphaned object properties. This is a semantic corruption, not a syntactic one, so TypeScript's type checking passes.
