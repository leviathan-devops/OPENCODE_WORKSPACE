# Memory Synthesis: v0.6.0 $\rightarrow$ HIVE-SKELETON v2

This document maps the "7 Memory Systems" of Hermes v0.6.0 into the new Mechanical Hierarchy.

| v0.6.0 System | HIVE-SKELETON v2 Location | Type | Mapping Logic |
| :--- | :--- | :--- | :--- |
| **Profiles** | `~/.hermes/profiles/{name}/` | Namespace | All memory is now siloed here. |
| **Session Memory** | `.../sessions/{id}/` | L1 State | Moved to `state.json` and `events.jsonl`. |
| **User Modeling** | `.../profiles/{name}/user.md` | L2 Truth | Now a dedicated file in the profile root. |
| **Local Notes** | `.../workspace/{project}/` | L2 Truth | Mapped to project-specific L2 files. |
| **Skills Library** | `~/.hermes/institutional/skills/` | L3 Truth | Moved to Global Institutional Core. |
| **MCP Sessions** | `.../sessions/{id}/mcp_logs/` | L1 State | Indexed as L0/L1 in the session la- la land. |
| **Remote Mounts** | `.../workspace/remote/` | L2 Truth | Mapped as external L2 pointers. |

**Synthesis Result:** 
The "7 systems" were not actually different *types* of memory, but different *locations* of data. By unifying them into a single L0/L1/L2 hierarchy, we eliminate the need for the agent to "choose" which system to use. It simply follows the path.
