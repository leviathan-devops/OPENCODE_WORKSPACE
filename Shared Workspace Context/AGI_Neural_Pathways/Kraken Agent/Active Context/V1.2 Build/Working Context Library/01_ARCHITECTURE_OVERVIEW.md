## Core Components

### 1. Brains (`src/brains/`)

| Brain | Role | Priority | Key Functions |
|-------|------|----------|---------------|
| **Planning** | Strategic intelligence, context generation | 100 | T2 Master, T1 Generation, Task Decomposition |
| **Execution** | Task execution coordinator, supervisor | 90 | Direct execution, Subagent oversight, Override authority |
| **System** | Active derailment detection, enforcement | 80 | L0-L7 Firewall, Gate evaluation, Real-time fix |

### 2. Roundtable Council (`src/brains/council/`)

| Cluster | Domain | Lead Sub-Brain | Focus |
|---------|--------|----------------|-------|
| **Alpha** | Steamroll builds | Execution | from-scratch, new-feature, aggressive |
| **Beta** | Precision tasks | Reasoning | debug, fix, refactor, analytical |
| **Gamma** | Testing | System | test, verify, audit, gates |

### 3. Shared Infrastructure (`src/shared/`)

| Component | Purpose |
|-----------|---------|
| `state-store.ts` | Domain-owned state management |
| `brain-messenger.ts` | Priority cross-brain messaging |
| `evidence-collector.ts` | Gate evidence collection |
| `domain-ownership.ts` | Domain ownership rules |

### 4. Subagent-Manager (`src/subagent-manager/`)

**Role:** Container-level parallel execution  
**Autonomy:** Fully autonomous with Execution Brain override  
**Key Function:** Output retrieval (the missing step!)

## L0-L7 System Brain Firewall

Unlike Shark's L0-L8 (code writing quality), Kraken's L0-L7 focuses on **ORCHESTRATION INTEGRITY**:

| Layer | Name | Purpose |
|-------|------|---------|
| **L0** | Identity Wall | Block non-Kraken agents from Kraken paths |
| **L1** | Orchestration Theater | "Task assigned" ≠ "Task complete" |
| **L2** | False Completion | Output retrieval must happen |
| **L3** | Output Inspection | Verify outputs on host filesystem |
| **L4** | Wrong Cluster | Alpha/beta/gamma domain enforcement |
| **L5** | Macro Derailment | Focus collision, planner-executor desync, context stale, premature completion |
| **L6** | Kraken Protection | Protect Kraken SYSTEM/CONFIG/STATE zones |
| **L7** | Coordination Gates | Task assignment, output retrieval, roundtable sync gates |

```typescript
  'container-state':    ['kraken-subagent'],
  'execution-queue':    ['kraken-subagent', 'kraken-execution'],
  
  // Cluster domains
  'alpha-state':        ['alpha-execution', 'alpha-system'],
  'beta-state':         ['beta-reasoning', 'beta-system'],
  'gamma-state':        ['gamma-system', 'gamma-execution'],

```

**Key invariant:** A brain can only WRITE to domains it owns. ALL brains can READ all domains.

## Brain Communication

### Priority Messenger

```typescript
const PRIORITY = {
  critical: 0,  // Gate failures, security blocks
  high: 1,     // Context injections, state changes
  normal: 2,   // Checkpoints, routine updates
  low: 3,      // Logging, monitoring
};

// Example
messenger.send({
  from: 'kraken-system',
  to: 'kraken-execution',
  type: 'gate-failure',
  priority: 'critical',
  payload: { gateId: 'output-retrieval-gate', taskId: 'xyz' },
  requiresAck: true,
});
```

### Synchronization Points

Brains run in **parallel** and only synchronize at **coordination gates**:

1. **task-assignment-gate** — Task assigned, cluster selected, context injected
2. **output-retrieval-gate** — Outputs retrieved, files verified, merge prepared
3. **roundtable-sync-gate** — All clusters reporting, no focus collision, council aligned

## Comparison: Shark vs Kraken Firewall

| Aspect | Shark L0-L8 | Kraken L0-L7 |
|--------|-------------|--------------|
| **Target** | Code writing quality | Orchestration integrity |
| **Identity Wall** | Block when agent uninitialized | Block non-Kraken from Kraken paths |
| **L1 Theatrical** | Counting patterns | Orchestration theater |
| **L2 False Completion** | (in L5) | Output never retrieved |
| **L3 Source Inspection** | File exists ≠ works | Output not on host |
| **L4 Wrong Container** | opencode container run | Wrong cluster assignment |
| **L5 Anti-Derailment** | Per-agent behavior | Focus collision, desync, stale context |
| **L6 Protection** | SYSTEM/CONFIG/PERSONAL | KRAKEN SYSTEM/CONFIG/STATE |
| **L7 Gates** | Code quality gates | Coordination gates |
| **L8 Behavioral** | Behavioral patterns | (not needed - mechanical) |

## Why This Architecture?

### Problems with v1.1
1. **Single-brain orchestrator** — One agent managing all clusters
2. **Fire-and-forget** — Tasks complete but outputs lost in containers
3. **No context layers** — No T0/T1/T2 distinction
4. **Manual injection** — Required human context injection
5. **No peer brains** — No triple-brain parallel execution

### Solutions in v1.2
1. **Triple-brain orchestrator** — Planning/Execution/System run in parallel
2. **Output retrieval enforcement** — System Brain ensures outputs retrieved
3. **Context layers** — T0/T1/T2 managed separately
4. **Self-generated context** — Planning Brain generates T1 from SPEC
5. **Roundtable Council** — Each cluster has its own brain
